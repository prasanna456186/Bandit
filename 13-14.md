# Level 13 → Level 14

This level is different from the earlier ones — instead of a password sitting in a file, I'm given an SSH private key (`sshkey.private`) and told it'll log me into bandit14, and the password is just sitting in `/etc/bandit_pass/bandit14` once I'm in.

## What I did

Checked what was in my home directory:

```bash
ls -la
cat sshkey.private
```

First instinct was to just try using the key directly, from inside the bandit13 session:

```bash
ssh -i sshkey.private bandit14@localhost
```

This is where I got stuck for a bit. It kept failing / behaving oddly, and after some digging I realized the issue: I was trying to SSH from *inside* the bandit server back to itself, using a key that's meant to be used from my own machine. `localhost` there refers to the Bandit server, not my computer, so I was basically trying to SSH from a machine to itself in a way that doesn't work cleanly for this setup.

The actual fix is to get the key onto my own laptop and connect from there instead. Used `scp` for that, run from my own terminal (not the SSH session):

```bash
scp -P 2220 bandit13@bandit.labs.overthewire.org:/home/bandit13/sshkey.private ~/Downloads/
```

Then, from my own machine, connected using that key and the port Bandit actually uses:

```bash
chmod 600 ~/Downloads/sshkey.private
ssh -i ~/Downloads/sshkey.private -p 2220 bandit14@bandit.labs.overthewire.org
```

That worked and dropped me into bandit14. From there the password was just sitting in the expected spot:

```bash
cat /etc/bandit_pass/bandit14
```
