# Level 12 → Level 13

This one took me the longest by far. The level description says `data.txt` contains a hexdump of a file that's been repeatedly compressed, and that I should work in `/tmp` since `~` has strict quotas.

## What I did

First, made myself a scratch folder in `/tmp` so I wasn't working directly in my home directory:

```bash
mkdir /tmp/bandit12
cp data.txt /tmp/bandit12/
cd /tmp/bandit12
```

`data.txt` isn't a normal file, it's the *hex representation* of one (that's what "hexdump" means here — you can tell just by opening it, it's all pairs of hex digits, not real binary). To turn it back into the actual binary file, `xxd` can reverse a hexdump with `-r`:

```bash
xxd -r data.txt > data.out
```

Then I checked what that actually was:

```bash
file data.out
```

It came back as gzip compressed data. So I renamed it with a `.gz` extension (mostly so the various compression tools don't complain) and unzipped it:

```bash
mv data.out data.gz
gunzip data.gz
```

Then checked the type again:

```bash
file data
```

This is basically where I settled into a loop — check the file type, rename it to match, decompress it, check again. It went through several rounds of gzip and bzip2, and at least one tar archive along the way:

```bash
mv data data.bz2
bunzip2 data.bz2
file data

mv data data.tar
tar -xf data.tar
file data5   # or whatever the extracted filename was

# repeat this cycle — rename, decompress/extract, check file type again
```

Every round the file got a bit smaller and the `file` output changed (gzip → bzip2 → tar → gzip again, etc.), until eventually `file` reported it as plain ASCII text instead of another compressed format. At that point I just did:

```bash
cat <finalfilename>
```

and that gave me the password. Honestly by the end I'd lost count of how many layers there were — I just kept doing "check type → rename to match → decompress/extract" until it stopped being compressed.
